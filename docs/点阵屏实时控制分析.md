# 点阵屏实时控制分析（2026-10-02）

依据：本机 ATK HUB Beta 3.2.6 前端代码（YOGO 75 PRO 使用 `EVISION_V2` 控制器），以及 v2 固件（V1.26 基础）的命令分发器、蓝牙 GATT 表反汇编。分析阶段没有向键盘发送屏幕命令；之后的有线演示只用了实时命令 0x3C/0x3D，没有写 Flash。

## 结论

| 连接方式 | 能否从电脑实时控制点阵屏 | 依据 |
|---|---|---|
| 有线 USB | **能**，固件原生支持，**已实测** | 配置接口 0xFF60 存在；固件处理 0x3C 实时帧命令。2026-10-02 用 `工具/点阵屏时钟演示.py` 实测，用户确认显示正常 |
| 2.4 GHz | 大概率能（未验证） | Hub 为 PID 4607 登记了无线控制器，每包数据缩小到 24 字节 |
| 蓝牙 | **不能**（现有固件） | 蓝牙只有 GAP、设备信息、电池、HID 四个服务；HID 报告表里没有厂商配置接口，也没有自定义服务。Hub 也没有为这款键盘登记蓝牙连接 |

## 屏幕规格

6×6 RGB 点阵。实时帧为 RGB565，36 个像素共 72 字节；静态图案为 RGB888，共 108 字节。

## 协议（USB，0xFF60 接口，64 字节报文）

报文头：`AA <cmd> <offset 低> <offset 高> <len> 00 00 00`，后面跟数据。

| 命令 | 作用 | 固件行为 |
|---|---|---|
| 0x10 | 开始会话 | 固件以 10 ms 为一拍计时，500 拍（5 秒）内没有命令就关闭会话；Hub 每 5 秒重新发一次 |
| 0x3C | 实时推送一帧 | 设置实时模式标志，清零超时计数；按 `offset/2` 写入像素，序号上限 36；RGB565 转为 RGB |
| 0x3D | 结束实时模式 | 恢复原来的点阵灯效 |
| 0x3B | 写入静态图案 | 写入帧缓冲，凑满 108 字节后**保存到 Flash**（会写存储，频繁调用不合适） |
| 0x11 | 结束会话 | |

实时模式下，50 拍（约 0.5 秒）没有新帧会自动退出，所以必须持续推帧。Hub 把每一帧拆成两包发送：offset 0 发 56 字节，offset 56 发 16 字节。像素按行优先排列，从上到下、从左到右：第 0 个是左上角，第 5 个右上角，第 30 个左下角，第 35 个右下角（已实测确认）。

Hub 里的「点阵屏音乐律动」用的就是这套接口：电脑分析音频频谱，生成 6×6 柱状图，持续推送。

## 实现实时控制（有线）

不需要改固件。电脑端程序用 hidapi 打开 0xFF60 接口，先发 0x10，然后按 10–30 fps 发送 0x3C 帧，每 5 秒内补发一次 0x10，结束时发 0x3D。可以显示 CPU 占用、时钟、通知、音频频谱等。macOS 上读取配置接口不需要输入监控权限，之前读取设置时已经验证过。

## 蓝牙要做到需要改固件

1. 在蓝牙报告表中加入厂商集合，带输出报告或特性报告，再在 GATT 表中加入对应的 Report 特征和 Report Reference 描述符；或者加一个自定义 GATT 服务。
2. 把蓝牙写入回调接到现有的配置命令分发器（0x0203EE48 处的跳转表）。
3. 报告表变化后，所有主机都需要重新配对。

蓝牙带宽足够（每帧 72 字节），主要工作量在 GATT 表和写入回调的补丁，需要离线验证加实机测试，风险比 v2 大。
